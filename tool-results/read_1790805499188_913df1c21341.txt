    50→    50→## 3. REGRAS DO JOGO — VERSÃO EXECUTÁVEL (complementa a spec)
    51→    51→
    52→    52→### 3.1 Numeração do tabuleiro
    53→    53→```
    54→    54→1 ─ 2 ─ 3
    55→    55→4 ─ 5 ─ 6      (5 = centro, “o cocó do meio”)
    56→    56→7 ─ 8 ─ 9
    57→    57→```
    58→    58→Internamente: `board[0..8]` ↔ casas `1..9`. A API pública usa **casas 1–9**.
    59→    59→
    60→    60→### 3.2 Linhas vencedoras (8)
    61→    61→`[1,2,3] [4,5,6] [7,8,9] [1,4,7] [2,5,8] [3,6,9] [1,5,9] [3,5,7]`
    62→    62→
    63→    63→### 3.3 Posição inicial e turnos
    64→    64→`P1: 1,2,3 · P2: 7,8,9 · vazias: 4,5,6`. **P1 joga sempre primeiro.** Um movimento de **uma** peça por turno, **obrigatório** (não há passar a vez).
    65→    65→
    66→    66→### 3.4 Movimento — decisão D1 (interpretação por omissão: `free-blocked`)
    67→    67→A spec diz “qualquer casa livre, sem saltar peças”. Interpretação fixada:
    68→    68→
    69→    69→- O **destino** tem de estar **vazio**.
    70→    70→- Se **origem e destino estão na mesma reta do tabuleiro** (linha, coluna ou diagonal pelo centro), **todas as casas entre elas têm de estar vazias**. Ex.: `1→9` exige `5` vazia; `1→3` exige `2` vazia; `2→8` exige `5` vazia.
    71→    71→- Se **não estão na mesma reta** (ex.: `1→6`, `2→4`, `1→8`), **não existe caminho a atravessar** e o movimento é **permitido** se o destino estiver vazio.
    72→    72→- Sem capturas. Sem substituir peças.
    73→    73→
    74→    74→> Implementar como `RulesConfig.movementMode`: `'free-blocked'` (omissão) | `'lines-only'` (só movimentos ao longo de retas, com caminho livre) | `'adjacent-only'`. **Só `free-blocked` vai para produção** — os outros existem para a decisão do Sama (Bloco 12) e para testes.
    75→    75→
    76→    76→### 3.5 Verificação de vitória — **ARMADILHA CRÍTICA (decisão D2)**
    77→    77→**Na posição inicial, P1 já ocupa a linha `1-2-3` e P2 já ocupa `7-8-9`.**
    78→    78→Se o motor verificar “todas as linhas, para qualquer jogador” após cada movimento, **P2 ganha logo após a primeira jogada de P1** (porque `7-8-9` continua intacta). Isto é um bug.
    79→    79→
    80→    80→**Regra:** depois de cada movimento, verificar **apenas as peças do jogador que acabou de mover**. Só esse jogador pode ter completado uma linha nesse movimento (as peças do adversário não mudaram). A posição inicial **não** é vitória para ninguém (o jogo começa em `READY`/`PLAYER_1_TURN`, sem verificação).
    81→    81→Consequência legítima: um jogador pode **sair** da sua linha de casa e **voltar** a ela mais tarde para ganhar — isto é jogável e está dentro das regras.
    82→    82→
    83→    83→### 3.6 Empate — decisão D3
    84→    84→Terceira ocorrência da **mesma posição completa + mesmo jogador a jogar** ⇒ `DRAW`. A posição inicial conta como 1.ª ocorrência. Chave: `"<casas P1 ordenadas>|<casas P2 ordenadas>|<jogador>"`. Opcional (config, desligado por omissão): `maxPlies`.
    85→    85→
    86→    86→### 3.7 Sem movimentos legais — decisão D4
    87→    87→Em `free-blocked` **é impossível** (provado por pesquisa exaustiva nos 3 360 estados — o teste exaustivo tem de confirmar). Nos outros modos existem estados sem movimentos. Comportamento configurável `noMovesOutcome`: `'lose'` (omissão) | `'draw'`. O motor nunca pode lançar exceção nem ficar bloqueado.
    88→    88→
    89→    89→### 3.8 Fim de jogo
    90→    90→Depois de `WIN_P1 | WIN_P2 | DRAW` nenhum movimento é aceite. Desistência e timeout online são resultados **de partida** (camada de match), não do motor de regras.

   124→   124→## 5. CONTRATO DO MOTOR (`packages/engine`) — A1 publica primeiro
   125→   125→
   126→   126→```ts
   127→   127→export type PlayerId = 'P1' | 'P2';
   128→   128→export type Square = 1|2|3|4|5|6|7|8|9;
   129→   129→export type Cell = PlayerId | null;
   130→   130→export type Line = readonly [Square, Square, Square];
   131→   131→export type GameStatus = 'READY'|'PLAYER_1_TURN'|'PLAYER_2_TURN'|'WIN_P1'|'WIN_P2'|'DRAW';
   132→   132→
   133→   133→export interface Move { from: Square; to: Square }
   134→   134→
   135→   135→export interface RulesConfig {
   136→   136→  movementMode: 'free-blocked' | 'lines-only' | 'adjacent-only'; // omissão: 'free-blocked'
   137→   137→  firstPlayer: PlayerId;            // omissão: 'P1'
   138→   138→  homeLineCounts: boolean;          // omissão: true  (ver Bloco 12 / D5)
   139→   139→  repetitionLimit: number;          // omissão: 3
   140→   140→  maxPlies: number | null;          // omissão: null
   141→   141→  noMovesOutcome: 'lose' | 'draw';  // omissão: 'lose'
   142→   142→}
   143→   143→
   144→   144→export interface GameState {
   145→   145→  board: readonly Cell[];           // length 9, index = casa-1
   146→   146→  currentPlayer: PlayerId;
   147→   147→  status: GameStatus;
   148→   148→  winner: PlayerId | null;
   149→   149→  winningLine: Line | null;
   150→   150→  moveCount: number;
   151→   151→  history: readonly Move[];
   152→   152→  positionCounts: Readonly<Record<string, number>>;
   153→   153→  config: RulesConfig;
   154→   154→}
   155→   155→
   156→   156→export type MoveErrorCode =
   157→   157→  'GAME_OVER'|'NOT_YOUR_TURN'|'INVALID_SQUARE'|'SAME_SQUARE'|
   158→   158→  'NOT_YOUR_PIECE'|'DESTINATION_OCCUPIED'|'PATH_BLOCKED';
   159→   159→
   160→   160→export type ValidationResult =
   161→   161→  | { ok: true }
   162→   162→  | { ok: false; code: MoveErrorCode; message: string }; // message em PT (Bloco 8.4)
   163→   163→
   164→   164→export function createGame(config?: Partial<RulesConfig>): GameState;
   165→   165→export function getLegalMoves(state: GameState, player?: PlayerId): Move[];
   166→   166→export function validateMove(state: GameState, move: Move, player?: PlayerId): ValidationResult;
   167→   167→export function applyMove(state: GameState, move: Move): { state: GameState; events: GameEvent[] }; // imutável
   168→   168→export function getWinningMoves(state: GameState, player: PlayerId): Move[];   // vitória imediata possível
   169→   169→export function getThreats(state: GameState, player: PlayerId): Threat[];       // destinos que completam linha
   170→   170→export function positionKey(state: GameState): string;
   171→   171→export function replayFrom(moves: Move[], config?: Partial<RulesConfig>): GameState[]; // estados 0..n
   172→   172→export function serialize(state: GameState): string; export function deserialize(s: string): GameState;
   173→   173→```
   174→   174→`GameEvent`: `MOVE_APPLIED | TURN_CHANGED | THREAT_CREATED | WIN | DRAW_BY_REPETITION | NO_MOVES`.
   175→   175→O motor é **puro e determinístico**: sem `Date`, sem `Math.random`, sem I/O.
   176→   176→
   177→   177→> **Atenção a bloqueios:** defender-se de uma ameaça pode ser feito **ocupando o destino** *ou* **ocupando uma casa do caminho** do atacante (no modo `free-blocked`). Por isso nenhuma parte do sistema pode assumir “bloquear = ocupar a casa vazia da linha”; deve perguntar ao motor (`getWinningMoves`, `getLegalMoves`).

   181→   181→## 6. IA (`packages/ai`)
   182→   182→
   183→   183→### 6.1 Níveis (spec §21–22)
   184→   184→| Nível | Comportamento |
   185→   185→|---|---|
   186→   186→| **Fácil** | ~30% jogadas aleatórias legais; caso contrário: ganha se puder, bloqueia ameaça imediata simples |
   187→   187→| **Médio** | Minimax profundidade 3–4 + avaliação (centro, ameaças, linhas abertas, mobilidade); evita repetição |
   188→   188→| **Difícil** | Minimax + poda Alpha-Beta (profundidade ≥ 8), deteta ciclos, ordenação de jogadas |
   189→   189→| **Perfeito** | Tabela pré-calculada por **análise retrógrada** dos 3 360 estados (ver 6.2): joga o caminho mais rápido para ganhar / mais lento para perder; em empate, evita repetições desnecessárias |
   190→   190→
   191→   191→Ordem de decisão base (spec §21): ganhar → impedir derrota imediata → criar ameaça dupla → impedir ameaça dupla → melhorar posição → centro → evitar repetição.
   192→   192→A IA **só** usa `getLegalMoves/applyMove/getWinningMoves` do motor. **Atraso de “pensamento” na UI:** 400–900 ms, configurável.
   193→   193→Todas as funções da IA são **puras** e aceitam uma `seed` para RNG reprodutível.
   194→   194→
   195→   195→### 6.2 Solver e relatório de equilíbrio (`tools/solver`) — **entregável obrigatório**
   196→   196→Espaço de estados = C(9,3)·C(6,3)·2 = **3 360**. Gerar a tabela retrógrada (vitória/derrota/empate + distância em jogadas) e escrever `docs/balance-report.md`.
   197→   197→
   198→   198→**Valores de referência já calculados por um resolvedor independente (a tua implementação TEM de os reproduzir — se não reproduzir, há bug no motor ou no solver):**
   199→   199→
   200→   200→- Modo **`free-blocked`** (omissão), regras por omissão: 3 360 estados; **0** estados sem movimentos; do ponto de vista de quem joga: **2 416 vitórias / 288 derrotas / 656 empates**.
   201→   201→- **Posição inicial = vitória forçada de P1 em 3 jogadas (plies: P1, P2, P1).**
   202→   202→  Exemplo: P1 joga `1→5` (ou `2→5`, ou `3→5`). Todas as 8 respostas legais de P2 perdem. Com `1→5`:
   203→   203→  `7→1` ⇒ P1 `2→7` · `7→4` ou `7→6` ⇒ P1 `2→7` ou `5→1` · `8→1` ⇒ P1 `3→8` · `8→4` ou `8→6` ⇒ P1 `3→8` ou `5→1` · `9→4` ou `9→6` ⇒ P1 `5→1`. (`9→1` é ilegal: passa por `5`.)
   204→   204→  Mecanismo: P1 sai da linha de casa e ameaça **voltar**; P2 só pode impedir ocupando a casa vazia, o que abre outra linha.
   205→   205→- Modo `lines-only`: 16 estados sem movimentos; posição inicial também vitória de P1 em 3 plies.
   206→   206→- Variante “linha de casa não conta” (`homeLineCounts:false`): `free-blocked` ⇒ P1 ainda ganha, em 9 plies; `lines-only` ⇒ **empate**.
   207→   207→
   208→   208→Converter os pontos acima em **testes de regressão**. **Não alterar as regras por omissão** por causa disto — o relatório serve para o Sama decidir (Bloco 12). A IA “Perfeita” deve refletir o resultado real (como P1 nunca perde; como P2 perde sempre contra jogo perfeito).

   212→   212→## 7. PRODUTO ONLINE, ECONOMIA E PROGRESSÃO
   213→   213→
   214→   214→### 7.1 ⚠️ Moeda e apostas — decisão D6 (limite legal/ético)
   215→   215→- Todas as “apostas” usam **moeda virtual (KZ virtual / moedas)**. **Não implementar** depósitos, levantamentos, gateways de pagamento nem conversão para dinheiro real.
   216→   216→- Flag `REAL_MONEY_ENABLED=false` (server + client), sem qualquer caminho de código ativo atrás dela.
   217→   217→- **Salas com aposta** e **Apostas ao Vivo**: confirmação de maioridade (18+) antes da 1.ª entrada, guardada no perfil.
   218→   218→- Mostrar aviso de jogo responsável (texto curto) nas Apostas e em Termos.
   219→   219→- O botão “+” junto ao saldo abre a **Carteira**: bónus diário, missões, histórico; compra de moedas fica como placeholder **desativado** (“Em breve”).
   220→   220→
   221→   221→### 7.2 Carteira / Ledger
   222→   222→Tabela `ledger_entries` (append-only, nunca `UPDATE/DELETE`): `id, user_id, delta, reason(enum), ref_type, ref_id, balance_after, created_at`. Saldo = soma/coluna derivada mantida por trigger. Operações sempre por **RPC/Edge Function** transacional; o cliente nunca escreve saldo.
   223→   223→Motivos: `WELCOME_BONUS, DAILY_BONUS, MATCH_STAKE_LOCK, MATCH_PAYOUT, MATCH_REFUND, BET_PLACED, BET_PAYOUT, TOURNAMENT_ENTRY, TOURNAMENT_PRIZE, ADMIN_ADJUST`.
   224→   224→Bónus de boas-vindas (banner do mockup: “ATÉ 5.000 KZ”): valor configurável; omissão: 5 000.
   225→   225→
   226→   226→### 7.3 Salas (ecrãs “Salas” e “Sala X”)
   227→   227→Sala = lobby com chat, lista de jogadores online, **aposta fixa por partida** (0 = grátis), capacidade (ex.: 24/50). Salas do mockup: **Luanda 100 KZ · Benguela 50 KZ · Huambo 25 KZ · Cabinda 10 KZ · Global 0 KZ (Free, cap. 100)** + **Angola** (destaque na Home). Filtros: **Todas · Online · Apostas · Amigos**.
   228→   228→Fluxo: Entrar na sala → ver jogadores/chat → **“Jogar”** (matchmaking na sala: fila por sala+aposta, par por `SKIP LOCKED`, preferir Elo próximo) ou desafiar jogador específico.
   229→   229→Mensagens de sistema tipo **Anúncio** (bolha verde, ícone “Anúncio”) geridas por admin.
   230→   230→
   231→   231→### 7.4 Partida online
   232→   232→- **Servidor autoritativo:** o cliente envia `{matchId, from, to}` para a Edge Function `submit-move`, que carrega o estado, valida com `@tira/engine`, grava em `match_moves`, atualiza a partida e devolve/emite o novo estado. O cliente só faz **atualização otimista** reversível.
   233→   233→- Realtime por canal `match:{id}` (+ fonte de verdade em DB para reconexão).
   234→   234→- **Relógio por turno:** 45 s (configurável). Mockup mostra contadores por jogador (“00:28 A sua vez” / “00:45 Adversário”). Timeout ⇒ jogada legal aleatória; **3 timeouts seguidos ⇒ derrota**. Prazo guardado como `turn_deadline` (o cliente só desenha a contagem; o servidor decide).
   235→   235→- **Desistir** (botão vermelho) e **Sair** (durante jogo = desistência) pedem confirmação.
   236→   236→- Reconexão: voltar à partida em curso; abandono > 60 s sem ligação ⇒ derrota.
   237→   237→- Fim de partida: Elo, XP, pagamento do prémio (pote = 2×aposta − taxa; `RAKE_PERCENT` omissão 0), histórico.
   238→   238→- Estados da partida: `WAITING → ACTIVE → FINISHED` com `result ∈ {P1,P2,DRAW}` e `reason ∈ {LINE, REPETITION, RESIGN, TIMEOUT, DISCONNECT, NO_MOVES}`.
   239→   239→
   240→   240→### 7.5 Progressão
   241→   241→- **Elo** inicial 1000, K=32 (omissão). **Rankings:** Semanal · Global · Amigos; pódio top-3 + lista.
   242→   242→- **XP/Nível** (perfil: “Nível 12 · 1.250 / 2.000 XP”): XP por resultado — vitória +30, empate +10, derrota +5 (tabela configurável); XP necessário por nível em tabela configurável (no mockup, o nível 12 pede 2.000 XP); barra de XP.
   243→   243→- **Estatísticas de perfil:** Vitórias, Derrotas, % Vitória = `vitórias / total de partidas` (empates contam no total).

Tudo com moeda virtual (7.1).
